# SmartWay 作业出题规则

> 适用场景：在 `homework/yuyue/`、`homework/yuxiao/`、`homework/common/` 下新增或修改作业页面（练习题）时。
> 公共讲解课/知识页（type=lesson）不适用本规则的"题面"和"交互"两节。

## 1. 孩子归属

- `yuyue` = **余跃**（小一些，四年级左右；题目数字应更小、可枚举）。
- `yuxiao` = **余晓**（六年级左右；题目难度可上一档）。
- `common` = 公共模块，所有孩子都能看到（讲解课、跨年龄通用题）。
- 兄弟两人的同主题题目要保持各自独立的页面，不要互相共用题面。

## 2. 题面措辞规则

新出题时严格遵守：

1. **不直接暴露题型分类**。题面里禁止出现明显归类提示词，例如：
   - 排列组合：禁止"排列""组合""单循环""无重复三位数"等一看就归类的术语。
   - 应改成生活化场景：握手、碰杯、合影、买水果、装礼物盒、排队、设密码、点套餐、发书等。
2. **每张题卡不显示题型徽章/标签**（不要用 `badge` 标"排列""组合"等），让孩子自己判断。
3. **题目顺序要打乱**，同类题不连续聚集；混合后整体看不出规律。
4. 题面要描述清晰但不啰嗦，控制在 2~4 行；必要的"是否分先后/顺序是否算新方法"信息可以隐性给出（如"装进同一个礼物盒""每人拿到的不一样""按顺序演出"）。
5. 名字优先使用孩子本人或常见小名（小明、小红等），让孩子有代入感。

## 3. 答案规则

1. 每题答案必须是**整数**，便于校验。
2. 答案数字应在孩子心算或列式可达范围（小学题尽量 ≤ 200，超过 500 的需有充分理由）。
3. 同一份作业中的 10 道题，答案可以有少量重复（题面完全不同时允许），但应避免大批量同答案。
4. 出题前自行验证每题答案，列出"题号 / 类型 / 算式 / 答案"清单核对。

## 4. 交互规则（练习页通用）

题型练习页（非讲解课）必须满足：

1. **答题过程中不显示对错**：输入框不实时校验、不染色、不显示"正确/错误"。
2. **必须全部题目都填写后**才允许点击"提交批改"。
   - 若有未填，提示哪几题未填（"还有 N 道题未作答（第 X、Y 题）"）。
   - 自动滚动并聚焦到第一个空题。
3. **批改时不展示正确答案**，只显示对/错（红/绿）和"正确"/"错误"两字。
4. 提供"重做"按钮可清空作答；提供"保存成绩"按钮在批改后可用，调用 `/api/children/{childId}/records`。
5. 答案应在 sessionStorage 中带 signature 自动保存，题目变更后自动作废。
6. 保留顶部"解题提醒/公式提示"卡片是 OK 的（这是讲方法，不是泄漏题型）。

## 5. 文件与注册规则

1. 新练习页放在 `homework/{childId}/{kebab-case-name}/index.html`；公共模块同理放 `homework/common/`。
2. 必须在对应目录下的 `tasks.json` 中注册一个条目（`id`、`name`、`type`、`description`、`entry`、`enabled`）。
   - `type` 可用值：`math`、`english`、`recitation`、`lesson` 等（讲解课用 `lesson`）。
3. 样式优先复用 `/shared/base-conversion-task.css`；可用 `<style>` 局部覆盖。
4. 不引入外部 CDN；图标/图示用 SVG 内联。

## 6. 部署规则

1. 修改完成后使用项目脚本一键部署：
   ```bash
   bash up_serv.sh "feat(模块): 改动简述"
   ```
   该脚本会：`git add -A → commit → pull --rebase → push → 调远端 update-github 接口拉取并重启`。
2. 远端拉取接口默认超时 60s，首次或大改动可加大：
   ```bash
   SMARTWAY_UPDATE_TIMEOUT_MS=180000 bash up_serv.sh "..."
   ```
3. 出题任务结束后，简要在对话里输出：题号、场景、类型（排列/组合/...）、答案，便于家长核对。**这只在对话里讲，不要写进 HTML 页面**。

## 7. 出题流程清单（每次出题都过一遍）

- [ ] 确认是给 `yuyue` 还是 `yuxiao`，难度匹配。
- [ ] 题面去除分类术语，使用生活情境。
- [ ] 答案全部为整数且已验算。
- [ ] 题型分布符合用户要求（如"排列 5 + 组合 5"）。
- [ ] 顺序打乱，相邻题不同类型为佳。
- [ ] 页面交互满足：未填完不可批改、批改不展示正确答案。
- [ ] `tasks.json` 已注册。
- [ ] 用 `up_serv.sh` 部署到服务器。
- [ ] 在对话里给家长一份"题号 - 类型 - 答案"对照表。
